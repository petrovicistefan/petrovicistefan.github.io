AI · generated codeFix sprint

The “vibe-coded” app works locally, then breaks in production

A prototype built fast with an AI assistant: missing validation, error handling and proper env config. With the first real users come corrupted data and blank screens.

How we fix it
  1. Code audit — map the critical flows (auth, payments, database writes).
  2. Add input validation, error boundaries and logging (Sentry / OpenTelemetry).
  3. Tests on the flows that make money, CI that blocks regressions.
  4. Hand over code your team can actually maintain.
Next.js · React 19Fix sprint

Hydration mismatch

Hydration failed because the server rendered HTML didn't match the client.

Dates, timezones, window, random IDs or browser extensions that touch the DOM make the server and client render different output.

How we fix it
  1. Reproduce on a production build and isolate the offending component.
  2. Move browser-only logic into useEffect / client components, use useId.
  3. Split Server and Client Components correctly and check caching.
API · browserExpress audit

Blocked by CORS policy

has been blocked by CORS policy: No 'Access-Control-Allow-Origin' header

Frontend and API on different domains, unhandled OPTIONS preflight, cookies sent with credentials against a * wildcard.

How we fix it
  1. Configure CORS server-side with an explicit origin allow-list (no * with credentials).
  2. Handle preflight at the gateway / CDN / reverse-proxy level.
  3. Where it makes sense, remove the problem entirely with a same-origin proxy.
WooCommerce · speedFix sprint

Slow WooCommerce store on mobile

LCP 4.8s · “Serve images in next-gen formats” · “Eliminate render-blocking resources”

Heavy JPEG/PNG product images, Google Fonts blocking render, too many plugins loading assets on every page, uncached cart fragments.

How we fix it
  1. Convert the media library to WebP/AVIF and serve responsive sizes.
  2. Drop external fonts for a system font stack, defer non-critical scripts.
  3. Load plugin assets only where needed, fix cart-fragment and object caching.
→ Zero-Config WebP Converter (free) → System Font Stack (free)
Core Web VitalsFix sprint

Poor INP in Search Console

INP issue: longer than 200ms (mobile)

Clicks feel sluggish: too much JavaScript on the main thread, third-party scripts (chat, tracking, A/B testing), needless re-renders.

How we fix it
  1. Measure on real-user data (RUM + CrUX), not just Lighthouse.
  2. Break up long tasks, defer third-party scripts, shrink the bundle.
  3. Validate in Search Console after the 28-day window.
Google · indexingExpress audit

“Crawled – currently not indexed”

How we fix it
  1. Technical audit: rendering, canonicals, robots, sitemap, internal links.
  2. Move key pages to SSR / SSG, fix metadata and schema markup.
  3. Prioritised report with estimated traffic impact.

Flagged by Lighthouse and accessibility audits — and a real legal risk under the European Accessibility Act and ADA for stores selling in the EU and US.

How we fix it
  1. Bulk-fill empty alt text from titles, then refine key product images.

Gmail · Outlook · YahooExpress audit

Emails land in spam or get rejected

550 5.7.26 Unauthenticated email is not accepted… DMARC policy

The big inbox providers now enforce sender requirements: without aligned SPF, DKIM and DMARC, invoices, order confirmations and password resets stop arriving.

How we fix it
  1. Inventory every service that sends mail on behalf of your domain.
  2. Set up SPF, DKIM, DMARC and one-click unsubscribe.
  3. Monitor DMARC reports and ramp the policy up to reject.

SecurityExpress audit

Exposed API keys and open databases

Secret keys in the frontend bundle or Git history, missing data-access rules (e.g. RLS in Supabase / Firebase rules) — anyone can read your tables.

How we fix it
  1. Scan code, Git history and the public bundle for secrets.
  2. Rotate keys, move them server-side, enforce access rules on every table.
  3. Secret scanning in CI so it doesn't happen again.

Payments · webhooksFix sprint

Payment webhooks failing or creating duplicate orders

No signatures found matching the expected signature for payload

The body is parsed before the signature check, there's no idempotency, and the provider's retries create duplicate orders.

How we fix it
  1. Verify against the raw body, separate keys per environment.
  2. Idempotent processing (each event exactly once) and a queue.
  3. Automatic reconciliation between payments and orders.
Auth · SafariFix sprint

Users get logged out at random

Wrong SameSite cookie settings, sessions across different subdomains, third-party cookie restrictions — especially on Safari and iOS.

How we fix it
  1. Reproduce on the affected browsers and trace the session lifecycle.
  2. Move auth first-party, set cookie attributes correctly.
  3. Secure refresh tokens and end-to-end tests on Safari.
Node · Docker · K8sMaintenance

Server keeps restarting (OOMKilled)

FATAL ERROR: Reached heap limit Allocation failed - JavaScript heap out of memory

Memory leaks, unbounded in-memory caches, container limits that don't match the workload.

How we fix it
  1. Heap snapshots and profiling under real load.
  2. Fix the leak, bound the caches, size resources properly.
  3. Alerts and dashboards so you see it before your customers do.
DatabaseFix sprint

Pages and APIs slow down as traffic grows

N+1 queries from the ORM, missing indexes, no caching — fine with 100 rows, not with a million.

How we fix it
  1. Measure real queries (EXPLAIN, APM).
  2. Indexes, eager loading, proper pagination and caching.
  3. Before/after report with response times.
Mobile · CSSExpress audit

Layout broken on phones

Horizontal scroll, buttons hidden under Safari's toolbar (100vh), the keyboard covering the form, images that jump around (CLS).

How we fix it
  1. Test on real iOS and Android devices.
  2. Dynamic viewport units (dvh, svh), safe areas, reserved space for media.
  3. Automated visual tests so it doesn't come back.
CI/CDExpress audit

“Works on my machine” — build fails in CI or on deploy

Different Node/package versions, missing env vars, import case-sensitivity, unpinned dependencies.

How we fix it
  1. Reproducible builds: lockfile, pinned versions, same container locally and in CI.
  2. Validate environment variables at startup.
  3. Preview deploys for every pull request.

How a fix works

No vague promises. Every step leaves something concrete behind.

You describe the problem

Error message, URL, when it started. We reply within one business day.

We reproduce it

No reproduction, no reliable fix. You get confirmation of the real root cause.

We fix + test

The fix lands in a pull request, with a test proving it won't come back.

We ship and watch

Deploy, post-launch monitoring and a short report of what changed.

FAQ

 

Do you work with clients outside Romania?

Yes — we work fully remote with teams and store owners across the EU, UK and US. We're on CET/EET, which overlaps with US East Coast mornings, and we communicate in English async-first (Slack, email, GitHub).

Do you work on code written by someone else (or by an AI)?

Yes — that's most of our projects. We take over legacy code, AI-generated prototypes and projects left behind by previous developers.

What access do you need?

Usually repository access and a staging environment. We only ask for production access when necessary, and you can revoke it any time afterwards. We're happy to sign an NDA.

How much does it cost?

Express audits and fix sprints are fixed-price, agreed before we start. You don't pay open-ended hours for an undefined problem. We invoice in EUR or USD.

Which stacks do you cover?

JavaScript/TypeScript (React, Next.js, Node), PHP / WordPress / WooCommerce, Python, SQL databases, Docker, Vercel, Cloudflare, AWS, plus AI API integrations.
